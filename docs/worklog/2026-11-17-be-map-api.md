# 메인 지도 조회 API를 API 명세서와 현재 시안에 맞춤

- 날짜: 2026-11-17
- 작성: Claude, 요청한 사람 소마고3
- 영역: be
- 기능 ID: REPAIR-7
- 브랜치·PR: `feature/map-api`, #11

## 한 일

- 지도 API 3개를 API 명세서, 기능 명세서, 시안(건물 탭 없음, 핀 색 구분 없음)과 대조했다.
- 층의 신고 목록과 핀 목록을 `GET /api/reports/map` 하나로 합쳤다. 응답에 `category`, `floorId`를 추가했다.
- 신고 API의 쿼리를 층 id(`floor`)에서 층 번호(`level`)로 바꿔, 세 건물의 같은 층 신고를 한 번에 받는다.
- 코드 주석과 `schema.sql` 주석의 "건물 탭" 표현을 정리했다.

## 바꾼 파일

- `controller/MapApiController`, `service/MapService`: 신고 API 쿼리와 응답
- `domain/Report`, `domain/Category`, `repository/*`: 신고에 분류 연결, 층 번호 조회
- `db/schema.sql`: 주석만 수정
- `docs/URL_PLAN.md`: 메인 쿼리와 신고 API 주소

## 맞춘 문서

- Notion: API 명세서(표, 화면 URL 쿼리, 변경 기록), "층의 신고 목록 조회(핀 포함)" 행, 기능 명세서 메인 페이지, ERD 설계(건물 탭 표현)
- repo: `docs/URL_PLAN.md`

## 정한 것과 미정

- 정한 것: 핀과 층 신고 목록을 하나의 API로 합침, 신고 API는 층 번호 기준
- 미정: 처리 상태에 "처리 중" 포함 여부

## 확인한 방법

- `mvn package` 성공.
- H2(Oracle 모드)에 `db/schema.sql`, `db/data.sql`을 넣고 임베디드 Tomcat 10.1에 `WebAppInitializer`부터 올려 HTTP로 호출했다. `/api/reports/map?level=3`이 서로 다른 건물의 3층 신고(`floorId` 3, 7)를 함께 돌려주고, `level` 누락·잘못된 값은 400, 없는 층 번호는 `[]`, `/api/buildings`와 `/api/floors/{id}/places`는 정상 응답이었다.
- Oracle에서는 확인하지 못했다.

## 남은 일, 다음에 할 일

- Oracle에서 `db/schema.sql` → `db/data.sql` 실행 후 API 호출 확인

## 요청 (다른 영역이나 담당자에게)

- FE: 메인 화면은 `level`로 신고 API를 한 번 부르고, `floorId`로 건물별 도면에 핀을 나눠 그린다.
