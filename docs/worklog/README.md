# 작업 기록 (제안, 팀 확정 전)

사람과 AI 에이전트(Codex, Claude 등)가 **무엇을 했고, 무엇을 정했고, 무엇이 남았는지**를 남기는 폴더다.
다음에 작업하는 사람이나 에이전트가 이 기록만 보고 이어서 할 수 있게 하는 것이 목적이다.
충돌이 나지 않게 하는 것이 최우선이라, 아래 규칙은 그 기준으로 정했다.

## 규칙

1. **PR 하나에 파일 하나를 새로 만든다.** 같은 파일을 여러 작업자가 고치지 않는다. 그래서 기록 때문에 충돌이 나지 않는다.
2. **파일 이름**: `YYYY-MM-DD-영역-내용.md` (영문 소문자와 하이픈). 영역은 `fe`, `be`, `db`, `docs` 중 하나.
   예: `2026-11-18-fe-main-map.md`, `2026-11-18-be-report-api.md`
3. **목록(index) 파일을 만들지 않는다.** 목록 파일은 모두가 고치는 공유 파일이라 충돌이 난다. 폴더 목록과 파일 이름으로 찾는다.
4. **기존 기록을 고쳐 쓰지 않는다.** 잘못된 내용은 그 파일 맨 아래에 `## 정정 (날짜)`로 덧붙이거나, 새 기록에서 바로잡는다. 다른 사람의 기록은 정정도 직접 하지 말고 알린다.
5. **템플릿**(`_TEMPLATE.md`)을 복사해서 쓰고, 항목이 해당 없으면 "없음"이라고 적는다. 길게 쓰지 않는다(한 화면 안팎).
6. **기준 문서와 다르게 쓰지 않는다.** 기능 명세, API, DB의 기준은 Notion과 `docs/URL_PLAN.md`다. 기록에는 "무엇을 바꿨고 어느 문서와 맞췄다"만 적고, 명세 내용을 다시 복사하지 않는다.
7. **정해진 것과 미정을 구분한다.** 팀이 합의하지 않은 내용은 "미정" 또는 "제안"으로 쓴다. 확정처럼 쓰지 않는다.
8. **적지 않는 것**: 비밀번호, 키, 접속 정보, 개인정보. 코드 전체를 붙여 넣지 않는다(파일 경로와 PR 번호로 가리킨다).
9. **언제 쓰나**: PR을 올릴 때 같은 브랜치에 함께 커밋한다. 코드 변경이 없는 조사·논의도 남길 가치가 있으면 쓴다. 사소한 오타 수정은 쓰지 않는다.
10. **누가 쓰나**: 작업한 사람이나 에이전트가 자기 작업만 쓴다. 에이전트가 썼으면 `작성`에 도구 이름(예: Codex, Claude)과 요청한 사람을 적는다.

## 이 폴더에 두지 않는 것

| 내용 | 두는 곳 |
| --- | --- |
| 기능 명세, 화면 구성, 시안 | Notion 기능 명세서, 디자인 페이지 |
| API 요청·응답 | Notion API 명세서 |
| DB 구조 | Notion ERD 설계, `db/schema.sql` |
| 팀이 정한 결정, 비교한 선택지 | Notion 기술 논의 사항 |
| 항상 지켜야 하는 규칙 | `AGENTS.md`, `docs/WORK_SPLIT.md`, `docs/GIT_CONVENTION.md` |

기록에서 위 기준 문서를 바꿔야 한다는 것을 알게 되면, 기록에 "요청" 항목으로 적고 해당 문서의 담당자에게 알린다.
